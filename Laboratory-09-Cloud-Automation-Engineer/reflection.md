# Laboratory 09 Reflection

In this laboratory activity, I learned how to automate tasks in Linux using Bash scripting and Cron. Before doing this activity, I understood that commands were used to manage files and folders, but I learned that these commands can also be placed inside a script to perform tasks automatically. I created a sample application folder, wrote a Bash script, and used it to compress the files into a backup archive. I also learned how to use `chmod +x` to allow the script to run.

Automation is important when managing hundreds of cloud servers because it saves time and reduces repetitive manual work. Instead of asking an administrator to back up files on every server, a script can perform the task according to a schedule. However, automation also has risks. For example, a wrong command in a script could delete important files or affect many servers if it runs everywhere. Because of this, scripts should be tested carefully before being used in an actual environment.

Writing a Bash script was different from creating a Docker Compose YAML file in Mission 6. Bash scripts contain commands that execute step by step, while Docker Compose YAML describes how containers and their services should be configured. Both tools are useful because they help make cloud operations easier and more organized.

From Laboratory 1 to Laboratory 9, my understanding of cloud computing has improved. I learned that cloud computing is not only about using online storage or servers. It also involves infrastructure, deployment, security, operations, and automation. Each laboratory helped me understand a different part of managing cloud environments.

The role I enjoyed most was the Cloud Automation Engineer because it showed me how technology can reduce manual work and make tasks more efficient. Overall, this laboratory helped me understand the importance of automation, careful testing, and proper documentation in cloud computing.
